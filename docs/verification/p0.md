Run `mise run demo` after the documented setup. Windows and the packaged browser
share the application's state transitions, view definition, text rasterizer and
typed HTTP action. Each running instance owns its own state. The shared editor,

framework. Production development-code exclusion has automated evidence.

## P0-D contract evidence

The initial contract experiment used MoonBit 0.10.11+6ff76a5f9 on 2026-09-06.
See [environment.md](environment.md) and `toolchain.json` for toolchain inputs.

- `rpc/core` defines contract metadata and typed in-process bindings; it has no transport.
- `examples/p0/backend/api` defines GetUser input, output, domain error and procedure.
- `examples/p0/backend/handlers` supplies success and NotFound cases.
- `examples/p0/frontend/app` imports only the API package.
- `scripts/verify-types.mbtx` checks isolated modules without backend handlers.

Procedure type parameters use `None` witnesses. Handlers are not part of the
contract. This binding experiment does not finalize a network client/server API.

The initial JS, WasmGC and native/MSVC runs each passed the handler test, frontend
execution, and the valid isolated check/build. All three targets rejected wrong
input, handler output, handler domain error, and client expected output types.
Compile-fail checks require a type-mismatch diagnostic, not just a nonzero exit.
These checks remain accessible through `mise run verify` and `mise run verify-native`.

## Initial P0 acceptance

The initial integrated P0 is accepted for the environments and operations recorded
above. This closes the prototype milestone, not general framework, editor or
distribution readiness. Ordinary physical input,
browser/native Japanese IME and the documented production presentation checks
are accepted for their recorded environments. Intermittent browser initialization
failure (#257), attachment shutdown (#275) and production system-key shutdown
(#311) remain unresolved investigations; a passing rerun is not a root-cause fix.
The maintainer deferred these three investigations on 2026-09-20: they are not
mandatory P0 gates and carry `status:awaiting-recurrence`. Do not run dedicated
reproduction loops. A recurrence during necessary verification must still fail
the check and retain its revision, command, environment and bounded diagnostics
before cleanup. Existing transport observations and opt-in process-exit capture
remain available; no timeout, assertion or cleanup requirement is relaxed.
Their current evidence and next steps belong in those Issues, rather
than reopening accepted IME checks. The bounded
[Narrator editor acceptance](native-accessibility.md#narrator-editor-acceptance)
is complete; it does not establish every screen-reader product or general IME
candidate behavior. The [accessibility checks](native-accessibility.md#observed-evidence-and-remaining-work)
cover forced mailbox delivery/close overlap, a delayed real SDK callback across
adapter recreation, and ordered application events around Close. Those bounded
schedules do not establish every possible interleaving or screen-reader usability.
Window close during a backpressured control response is covered by the
[integrated control verification](../development.md#integrated-window).
Limits are not passes.

Protobuf/gRPC is an optional adapter experiment. It is not a dependency of the
standard HTTP/JSON path and does not block P0 completion. R1/G1/N1 remain later
milestones, not claims made by this prototype.
