# P0 verification index

This index links to reproducible evidence and remaining acceptance criteria.
A headless rendering or synthetic input result does not establish real IME,
visible-window behavior, OS accessibility, or production distribution readiness.

| Area | Evidence | Remaining boundary |
| --- | --- | --- |
| Integrated application | [Demo and common operation sequence](integrated-demo.md) | Full physical-input and production usability acceptance |
| Browser GPU | [JS/WasmGC comparison](browser-gpu.md), [selected WasmGC package](browser-target.md) | Real browser IME and editing parity |
| Native GPU | [wgpu-mbt adoption](wgpu-mbt.md), [owned-window presentation](native-presentation.md) | Glyph agreement, real input and DPI acceptance |
| Async and HTTP | [Native async](native-async.md), [browser async](browser-async.md), [UI HTTP failures](ui-rpc-failures.md) | Task-scope and HTTP cases are verified; physical device loss and arbitrary foreign-thread closures are outside that evidence |
| Control and accessibility | [CLI/MCP](native-control.md), [production AccessKit](native-accessibility.md) | Text geometry and actual assistive-technology use; launch-scoped control does not attach to arbitrary processes |
| Text and IME | [Positions](text-positions.md), [font layout](text-layout.md), [real IME procedure](native-ime.md) | Physical Japanese composition/candidate placement, glyph agreement and editing limitations listed in the demo |
| Dependencies | [Library reuse](library-reuse.md), [dependency record](dependencies.md) | Remaining external boundaries and deferred replacements are tracked in Issues |

Run `mise run demo` after the documented setup. Windows and the packaged browser
share the application's state transitions, view definition, text rasterizer and
typed HTTP action. Each running instance owns its own state. The shared editor,
Load user button, result area, task controls and status are integrated; this is not yet a general UI
framework. Production development-code exclusion has automated evidence, while
physical input and real IME remain unverified requirements.

## P0-D contract evidence

The initial contract experiment used MoonBit 0.10.11+6ff76a5f9 on 2026-09-06.
See [environment.md](environment.md) and `toolchain.json` for toolchain inputs.

- `rpc/core` defines contract metadata and typed in-process bindings; it has no transport.
- `examples/p0/backend/api` defines GetUser input, output, domain error and procedure.
- `examples/p0/backend/handlers` supplies success and NotFound cases.
- `examples/p0/frontend/app` imports only the API package.
- `scripts/verify-types.mbtx` checks isolated modules without backend handlers.

Procedure type parameters use `None` witnesses. Handlers are not part of the
contract. This binding experiment does not finalize a network client/server API.

The initial JS, WasmGC and native/MSVC runs each passed the handler test, frontend
execution, and the valid isolated check/build. All three targets rejected wrong
input, handler output, handler domain error, and client expected output types.
Compile-fail checks require a type-mismatch diagnostic, not just a nonzero exit.
These checks remain accessible through `mise run verify` and `mise run verify-native`.

## Remaining P0 acceptance criteria

P0 as a whole is not complete. The evidence table above distinguishes the
integrated implementation from unverified requirements. Physical input, Japanese
IME, remaining presentation/glyph agreement, complete accessibility usability and
forced accessibility callback/close interleavings need their own acceptance evidence.
Window close during a backpressured control response is covered by the
[integrated control verification](../development.md#integrated-window).
Limits are not passes.

Protobuf/gRPC is an optional adapter experiment. It is not a dependency of the
standard HTTP/JSON path and does not block P0 completion. R1/G1/N1 remain later
milestones, not claims made by this prototype.
