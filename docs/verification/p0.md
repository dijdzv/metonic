# P0 検証記録

2026-09-06。MoonBit 0.10.11+6ff76a5f9でP0-Dの型境界を検証。
環境と取得アセットは [environment.md](environment.md) と toolchain.json に記録。

## 実装済み

- `rpc/core`: 契約metadataと型付きのプロセス内binding。通信処理はない。
- `examples/p0/backend/api`: GetUserのInput、Output、業務エラー、Procedure。
- `examples/p0/backend/handlers`: 成功とNotFoundを返すサンプル。
- `examples/p0/frontend/app`: APIだけをimportする実行例。
- `scripts/verify-types.ps1`: backend/handlersが存在しない独立moduleで正負の試験。

Procedureの型引数は`None`の型witnessで保持する。handlerは契約には入らない。
`Binding`はP0の型合わせ実験であり、将来のnetwork client/server API確定ではない。

## 実行結果

`scripts/verify.ps1` と `scripts/verify.ps1 -Native` をPowerShell 7で実行。

| 検証 | WasmGC | JS | native/MSVC |
| --- | --- | --- | --- |
| 成功・業務エラーの単体テスト | 1/1 pass | 1/1 pass | 1/1 pass |
| FEの起動（users.get.v1 / 1） | pass | pass | pass |
| backend実装なしの正しい呼び出しをcheck/build | pass | pass | pass |
| 誤ったInputを拒否 | pass | pass | pass |
| 誤ったhandler Outputを拒否 | pass | pass | pass |
| 誤ったhandler DomainErrorを拒否 | pass | pass | pass |
| 誤ったclient側期待Outputを拒否 | pass | pass | pass |

型拒否試験は単なる非0終了ではなく、診断にtype mismatchがあることも確認する。
毎回新しい`.work/typecheck-<id>/`で実行し、stdout/stderrログを保存する。
生成物と機器固有の絶対パスを含むログはGit対象外。再現スクリプトと結果をコミットする。
`moon fmt --check`も成功。
最終的に `mise run verify` / `mise run verify-native` の入口からも成功を確認した。
