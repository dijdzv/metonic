# 固定設定の評価と試作の完了条件

## 対象と固定条件

FULL-INVENTORY.mdの固定worktree・フック対象1,880項目を毎回送る。
親コマンドと子検証が共存するため、除外件数を独立したテスト件数や時間短縮率としない。
symbolsモードを基準とし、本文・ソース全文は送らない。
基準入力はhook-inventory.json。拡張シンボルは別候補として扱う。
見逃し・安定性・除外効果が同程度なら、送信文字数と入力トークン数が少ない形式を採用する。
全件送信は維持し、重複メタデータや効果の薄い参照情報を削減候補にする。
有料比較は代表Diffで候補を絞ってから広げる。既存応答を再利用できる集計では再送しない。
compact-symbolsは質問キーと重複するtest.idとnullの任意項目だけを省く比較候補。
テスト名・所在・参照シンボルは維持する。入力構造の変更も判定へ影響し得るので、
文字数が減っただけでは採用確定にしない。
省略候補はscore <= 0.5、confidence >= 0.6、P(0) >= 0.6。
既存の応答検証と強制実行条件を維持する。API欠落・不正・不明は実行に残す。

## 評価手順

1. 約20件の異なるDiffを用意し、調整用と未使用評価用に分離する。
   UI、非同期、状態管理、保存、ホスト、検証スクリプトを含める。
2. API呼出し前に各Diffの影響対象と根拠を記録する。
   過去の実行で失敗を確認した対象と、静的に影響が期待される対象を区別する。
   静的な対象一覧は完全な正解集合とは呼ばない。
3. 同じDiff・一覧・入力形式・閾値で各3回評価する。
   全件の送信と応答を照合し、欠落、誤除外、判定の揺れ、API利用量を保存する。
   model_runと最終runを分け、変更ファイルの強制実行で救われた誤判定も記録する。
   強制実行対象を残しただけではモデルの正解と数えない。
4. 未使用評価用を見て調整したら、その集合は未使用とは扱わない。
   追加情報は改善と費用を比較し、効果が確認できない拡張を積み上げない。

## 完了判定

全件送信・安全側処理が成立し、未使用評価用で根拠付き影響対象の誤除外が
観測されず、反復時の揺れと入力費用を記録できた段階で推奨設定を確定する。
誤除外が出たら原因を分類し、修正または適用範囲の制限を明記する。
削減率の目標は置かない。20件・3回は実験を有限にする目安で、安全性の証明ではない。

今回テスト本体は実行しない。真の影響対象を網羅できないため、実際の見逃し率は
未測定とする。スコア・confidence・確率値も正解率として解釈しない。
成果は試作完了と推奨設定であり、フックでの自動省略導入とは分離する。
