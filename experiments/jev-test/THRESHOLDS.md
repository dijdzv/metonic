# 閾値と依存解析の比較（2026-09-26）

## 現在の実装

省略条件はすべてAND:

- score <= 0.1
- confidence >= 0.98
- probabilities["0"] >= 0.98

回答形式不正・欠落・範囲外・確率合計不整合は実行。
変更されたテストファイル、force_allの場合も実行。
これらは安全性を校正済みの数値ではなく、試作開始時の仮値。
Metonicの直近2故障では全286件を選択するため、省略効果なし。
confidenceとP(0)に同じ下限を使っているが、意味が同一だからではない。
今後は別パラメータとして校正する必要がある。

比較候補はscore<=0.5、confidence>=0.6、P(0)>=0.6。
これは保存した応答に対する探索用であり、標準設定やフックに採用していない。
参考実装の4段階Scoreとこちらの3段階Scoreでは数値を直接移植できない。

## ユーザーの検証メモから取り入れる点

メモは過去の別用途でのユーザーの観測であり、テスト選択で独立再現した結果ではない。
採用する設計原則は、判断と実行方針の分離、数値分布と正解率の区別、用途別の校正、
モデル更新時の固定評価データによる比較。Choice/Noulの閾値や200〜300msという
観測値は今回の長いコード入力へそのまま移植しない。

現行rubricの段階1は「不明」と「間接関係」を混在させている。高confidenceで
段階1になることは、影響の証拠が強いこととも、情報不足を明確に判定したこととも
区別できない。次のrubric比較では、影響・結果変化の程度を一貫した軸に置き、
不確実性や根拠不足は別に扱う。ただしrubric変更時は過去の応答を流用して校正しない。
モデルに「安全に省略できるか」という広い自己評価を追加して済ませない。
