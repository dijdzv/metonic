# Jevフィルターの固定設定評価

この文書は3段階方式の評価記録。後続の5・6段階比較を含む最終推奨は
[LEVELS-COMPARISON.md](LEVELS-COMPARISON.md)の条件付き4段階を参照する。

## 結論

今回の試作の推奨入力は **compact-symbols**。
Diff・変更ファイル・全対象の名前/所在/種別/参照シンボルを送り、重複IDとnull項目を省く。
省略候補の条件は **score <= 0.5、confidence >= 0.6、P(0) >= 0.6**。
通常symbolsを比較基準にし、未使用集合へ送る前に圧縮形式と条件を固定した。
見逃し・安定性が同程度なら入力を減らす方針に沿った選択で、これ以上の情報追加は行わない。

20 Diff × 3回 = 60回の評価を完了。全回でフック対象1,880項目を送り、
合計112,800件の回答を受領した。ID集合とAPI分割後の質問数を照合し、欠落0。
使用モデルは全回jev-1.13.0。調整用10件と未使用評価用10件を分離し、
評価結果を受けた閾値・入力の再調整はしていない。

## 影響対象を残せた範囲

- 過去の実行で失敗確認済み：5 Diff、7組のDiff/対象対応 × 3回。誤除外0。
- 静的に影響を特定：15 Diff、48組 × 3回。誤除外0。
- 上記のうち未使用集合：10 Diff、30組 × 3回。誤除外0。

モデル単体の判断と、必須実行などの安全策適用後の判断の両方で0だった。
bootstrapと型契約は変更された検証ファイル自身なので、安全策でも保持される。
それらをモデル正解へ無条件に算入せず、モデル単体の判定も確認した。
静的期待は実装とassertを照合してAPI評価前に固定。実際に失敗させた結果ではない。
同じ領域の別変更を含むため、未使用集合でも未知のサブシステム一般への保証はしない。

**今回テスト本体は実行していない。真の影響集合は未確定なので、実際の見逃し率は未測定。**
55組は完全な正解集合ではなく、反復やbackend別の対応も独立な標本とは扱わない。
60回で誤除外を観測しなかったことから安全確率を算出しない。

## 費用と判定の揺れ

ラベルDiffの比較では、通常symbolsの入力589,721 tokens/回に対し、
compact-symbolsは472,040 tokens/回で約20.0%減少した。
生成JSON文字数も1,875,197から1,570,766へ約16.2%減った。
全1,880項目でnull以外の根拠情報が維持されることを機械的に照合済み。
ナビゲーションDiffでも589,455から471,850へ同程度減少した。
通常symbolsのラベル反復は除外295–307件、圧縮後は371–378件。
圧縮だけで判断が変わるため、除外増加を精度向上の証拠にはしない。
通常形式のラベル反復で揺れた86項目に対し、圧縮形式は114項目だった。
両形式の精度・安定性が統計的に同等と証明したわけではない。
今回確認した影響対象を保持しつつ入力費用を減らせた、試作段階での推奨とする。

固定形式60回の合計：入力28,306,740 tokens、出力3,346,740 tokens。
平均1回：入力約471,779、出力55,779 tokens。これは60回の評価費用であり、
初期比較や通常symbolsの事前実験を含むプロジェクト全体の請求総額ではない。
金額は契約・料金に依存するため換算していない。
API処理時間は平均28.95秒、範囲26.49–37.34秒。収集やテスト実行の時間ではない。

除外候補は186–1,705項目。固定した削減率目標は置かなかった。
カタログは親コマンドと子の検証を含み、この件数を独立テストの削減数や時間短縮率に換算しない。
1 Diff内で判断が揺れた項目は72–183件あり、完全に安定した選別ではない。
3回共通の除外数は安定性の観察用で、通常運用で3回課金して合議する提案ではない。

## 安全側処理と再現

欠落応答、不正な確率合計、別Diffに結び付いた古い応答を与えた計画生成では、
各1,880項目すべてが実行に残った。追加のAPI通信やテスト本体実行はしていない。
実APIの入力上限では質問群を分割し、全IDを保持した。

評価ケースはevaluation-cases.json、収集範囲はFULL-INVENTORY.md、手順はEVALUATION-PROTOCOL.md。
実験データは.work/jev-metonic。frozen-evaluation-report.jsonが全60回の明細、
final-comparison-summary.jsonが反復比較、final-response-audit.jsonが応答と利用量の照合結果。
`evaluation-report CASES DIRECTORY OUT`で保存応答をAPI再呼出しなしに再集計できる。
全20 Diffの適用可能性、各一覧の1,880 ID一致、期待IDの存在を確認した。

試作の評価と推奨設定の確定は完了。既存フックによる自動省略は導入していない。
混在する検証種別の実行計画への集約、実際の見逃し率、実行時間短縮は今回の成果に含めない。
今回の推奨設定ではソース全文・テスト本文の追加は採用しない。

## 参考実装との尺度の違い

2026-09-26にmizchi/jev-test-filterのsrc/questions.tsとsrc/gate.tsを確認。
参考実装は0=無関係、1=触れたコードを使うが結果は変わらない、2=失敗し得る、
3=失敗の可能性が高いという4段階。既定cutoff=2、unsureBelow=0.5、unsureMargin=1。
こちらの1は不明・間接関係で実行側、2は直接影響であり、数値は互換ではない。
保存済みの3段階回答へ参考実装の閾値を適用したり、単純に比例換算したりしない。

参考にする価値があるのは「変更に関係するがテスト結果は変わらない」を独立した
段階として扱う点。単なる関連度より結果への影響を問う設計は、不要な実行を減らす
候補になる。ただしその区別を正しく判断できるかは別の評価が必要。
今回は推奨形式・閾値を維持し、追加のAPI呼出しはしない。
4段階化する場合は新しい評価方式として少数の代表Diffから比較し、過去60回の
3段階評価と混ぜない。閾値だけの比較は保存応答を再利用する。
